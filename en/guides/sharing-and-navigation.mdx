OpenYida can configure page share settings after a page is created and published.

## Link types

| Link type | Path | Audience | Use case |
| --- | --- | --- | --- |
| Public access | `/o/<slug>` | Anyone with the link | Static pages that do not require Yida login. |
| Organization share | `/s/<slug>` | Internal users through DingTalk/Yida SSO | Internal dashboards, reports, and business pages. |

<Warning>
Do not use `/o/` public access for pages that call Yida form APIs. Anonymous users cannot call login-protected Yida data APIs. Use `/s/` organization share instead.
</Warning>

## Configure an internal short link

Always verify the path before saving it:

```bash
openyida verify-short-url <appType> <formUuid> /s/my-dashboard
openyida save-share-config <appType> <formUuid> /s/my-dashboard y
openyida get-page-config <appType> <formUuid>
```

The final URL is:

```text
https://www.aliwork.com/s/my-dashboard
```

## Configure public access

For a pure static page:

```bash
openyida verify-short-url <appType> <formUuid> /o/my-public-page
openyida save-share-config <appType> <formUuid> /o/my-public-page y n
```

The optional last argument is `openAuth`:

| Value | Meaning |
| --- | --- |
| `y` | Require authorization. |
| `n` | No authorization required. |

## Disable sharing

```bash
openyida save-share-config <appType> <formUuid> "" n
```

## Hide or show the platform navigation

```bash
openyida update-form-config <appType> <formUuid> false "Page Title"
openyida update-form-config <appType> <formUuid> true "Page Title"
```

Use hidden navigation for full-screen dashboards, executive reports, and presentation-style pages.
