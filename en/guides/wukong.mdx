Wukong workspaces use dynamic paths and a bundled Node.js runtime. OpenYida detects Wukong through the active environment, but shell commands may still need the Wukong Node path.

## Workspace detection

Wukong workspace paths usually look like:

```text
~/.real/users/{uuid}/workspace/
```

OpenYida reads `AGENT_WORK_ROOT` when present and uses it as the workspace root.

```bash
openyida env --json
```

## Node.js path

Before running `node`, `npm`, or `npx` inside Wukong, put Wukong's bundled Node.js first in `PATH`.

macOS/Linux:

```bash
export PATH="$HOME/.real/.bin/node/bin:$PATH"
```

Windows PowerShell:

```powershell
$env:PATH = "$env:USERPROFILE\.real\.bin\node\bin;$env:PATH"
```

This avoids accidentally using a system Node.js installation with different permissions.

## Initialize a workspace

```bash
openyida copy
openyida env --json
openyida login
```

When the Wukong workspace is empty, `openyida copy` lays the `project/` template directly into the workspace instead of adding an extra nested `project/` directory.

## Skills package

Wukong uses a manually uploaded skill package. Build it from the OpenYida repository:

```bash
npm run build:skills
```

The generated package is written to:

```text
dist/skills/openyida/
openyida-skills.zip
```

The Wukong package keeps only one root `SKILL.md`; child skill docs are converted into `references/subskills/`.
